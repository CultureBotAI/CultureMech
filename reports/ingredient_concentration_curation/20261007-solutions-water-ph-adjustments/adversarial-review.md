# Adversarial Review

## Addressed Before Apply

- A simple pH instruction does not prove a final volume. Each correction uses
  only the explicit source water input and converts ml to L; nominal dataset
  volume is checked solely to diagnose the old import encoding.
- Reusing the preceding 1 L correction could overwrite smaller water inputs.
  The inspected source amounts are pinned individually; the independent audit
  covers 500, 800, 900 and 1000 ml cases without summing other liquids.
- A broad preparation pattern could approve unseen records. The new CLI pins
  the complete 158-record context and accepts only the 107 inspected selections.
  Source bytes, metadata and the whole baseline object must match. In-memory
  context modification is also rejected before constructing the adapter.
- Existing water evidence or contextual notes could be erased. Such context
  blocks the common helper; full-record inversion checks every unrelated field
  and all prior provenance. There is no change to the general reviewer's guard.
- Reuse could invalidate the earlier pH-7 curation. Its full frozen plan,
  persisted results and original adversarial tests are checked for compatibility.
- An already-applied plan could conceal modified claims. Plan validation
  recomputes every result before apply or verify; no-op reruns are also checked.
- A concurrent edit to the last target could leave a partial batch. The shared
  apply preflights all pending files before writing; a regression test covers it.
